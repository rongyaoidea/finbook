## 0. 结论摘要

1. **两者不是同一类产品**。金蝶（AI 星瀚/星空/星辰 + 苍穹平台）与用友（YonBIP 6 / NC / U9 /
   U8 / T+/ YonSuite）是覆盖财务、税务、资金、供应链、制造、HR、PLM、协同、AI、生态的
   **全领域云 ERP 套件**；FinBook 是一款**可自托管、单文件账套（SQLite）的轻量财务 + 进销存软件**。
2. **基础核算桌面端可打**：凭证→账簿→报表→期末结账→银行对账→往来核销→固定资产→工资个税→
   预算→自定义报表这条主线在桌面端基本闭环，且部分口径（结账线守卫、试算平衡、累计预扣、
   UFO 公式）做得扎实。
3. **Web（多租户）端只覆盖子集**：无固定资产、无期末结账/损益结转、无银行对账、无附件上传、
   无自定义报表；分录上无法录入辅助核算/数量/外币（银行科目辅助会被自动填，
   启用其他辅助核算的科目在 Web 无法保存）。
4. **供应链/制造当前不具备可用的业务闭环**：采购订单、销售订单、BOM、生产订单**在桌面与 Web
   都没有创建/修改入口**，`po_save/so_save/bom_save/prod_save` 仅被测试调用；到货/发货只写流水、
   不联动库存，订单执行进度仅按流水动态汇总且无页面；MRP 只写结果快照，不生成请购/生产/采购
   建议。对标文档中该部分的 ✅ 属于严重高估。
5. **与两家差距最大的不是功能清单数量，而是六个系统性维度**：多组织与报表合并、税务/发票/
   电子档案合规链、开放 API 与生态、AI 能力、性能与高可用架构、实施/服务体系。
6. **FinBook 的真实优势**：数据与部署完全自主（内网/离线/WireGuard）、免订阅、源码可得（MIT）、
   单文件备份恢复、免实施、可审计。适合 1~10 人、单法人、独立账套的小微/内勤财务与进销存；
   **不适合**多组织集团、复杂制造、税务直连、需要移动端/生态/AI 与大并发的场景。

## 1. 对标口径与产品分层

| 档位 | FinBook | 金蝶 | 用友 |
|---|---|---|---|
| 大型/集团 | —（无多组织/合并） | 金蝶 AI 星瀚（央国企/大型） | YonBIP 6 / NC Cloud（大型、超大型） |
| 中型 | 桌面端单法人可用 | 金蝶 AI 星空（原“云星空”，2025 更名，成长型企业） | U9 Cloud（中大型制造）、U8 Cloud（中型） |
| 小型/成长 | Web 多租户（功能子集） | 金蝶 AI 星辰 | YonSuite、T+ Cloud |
| 小微/代账 | ✅ 本命场景 | 精斗云等 SaaS 系列 | 畅捷通（好会计/易代账等） |
| 部署 | 私有化单机/自托管（HTTP，建议 WireGuard/内网） | 公有云 SaaS 为主，支持私有云/混合云（星空） | 公有云为主，BIP 支持专属云/本地部署 |
| 收费 | 一次性/免费（MIT 源码） | 订阅（模块 × 用户）或买断 + 实施 | 订阅/许可 + 实施 |
| 扩展 | 二次开发需改源码 | 苍穹 aPaaS、云市场、OpenAPI | iuap 低代码、连接器、OpenAPI、生态 |

> 结论：**正确对标对象其实是“精斗云 / 畅捷通 T+”这一档**，而不是云星空 / YonBIP。
> 旧文档直接对标云星空与 T+Cloud 并给出 95% 完成度，口径本身就不成立。

## 2. 功能对标（按领域）

图例：✅ 可用（桌面/Web 标注）· 🟡 部分（括号内写明缺口）· 🧱 仅数据层/测试级 · ❌ 无

### 2.0 Web 端能力边界（先说清楚）

Web（`finweb`，多租户服务端）与桌面（`finui`）不是同一条产品线的能力集合，比较时必须分开：

- **Web 已具备**：平台/账套/用户管理、科目 CRUD、期初余额录入、凭证与期初导入（金蝶/用友模板）、
  凭证录入/修改/记账/反记账/红冲/删除/批量记账、凭证模板 CRUD、辅助档案 CRUD、
  明细账 JSON + 套打（type=detail）、科目日报、余额表/多栏账/摘要汇总/财务指标、
  三大报表与对比/对账、存货成本调整、序列号/多单位/账龄/ABC/组装拆卸/分仓结存 API、
  采购请购/到货/付款/退货/暂估/对账/配额（流水与只读报表）、销售报价/发货/收款/退货/信用检查、
  坏账计提、预算版本元数据 + 分析 + 预警、资金票据/融资/日报/预测、成本配置 + 期末结价、
  审批中心、报表附注、电子档案、工资/报销全流程、备份恢复、操作日志。
- **Web 缺失（桌面有）**：期末结账/反结账/损益结转、自动转账、汇率调整、固定资产、
  银行对账、往来核销与账龄、预算金额编制、多维损益、自定义报表、凭证附件上传、
  凭证/账簿/工资/报销导出、总账/日记账交互页面。
- **两端都缺**：凭证审核/作废入口、数量金额账/辅助账、报表合并、银企直连、电子发票/申报、
  采购/销售/生产订单创建与流转、盘点、调拨配对、预算控制、审批驱动业务、
  部门数据范围过滤、开放 API 鉴权体系、AI/移动端/插件。

## 3. 非功能性对标

| 维度 | FinBook | 金蝶/用友（云版本） |

## 5. FinBook 的真实优势与适用边界

**优势（相对金蝶/用友同档 SaaS）**
- 数据完全自主：单文件账套 + 本地/内网部署，满足“数据不出门”的强要求；WireGuard 内网访问已验证。
- 无订阅与许可成本，源码 MIT 可得，可审计、可定制（代价是自运维）。
- 部署极简：一个二进制 + 一个文件，免实施、免中间件，备份=复制文件（VACUUM INTO）。
- 单机性能对小体量足够：余额快照实时算，凭证-账簿-报表口径一致，跨月改单立即正确。
- 桌面端财务闭环完整度对小微场景足够（结账/对账/核销/资产/预算/自定义报表）。

**适用边界（不建议承接的场景）**
- 多法人/集团合并、组织间交易、内部结算、责任中心核算。
- 复杂离散/流程制造（BOM 维护、APS、MES、质量、工单成本）。
- 需要电子发票、纳税申报直连、银企直连、电子档案合规的场景。
- 需要移动 App、开放 API 生态、AI 助手、BI 自助分析的场景。
- 数十人以上并发、要求高可用/SLA/等保认证的场景。

## 6. 差距优先级路线图（以“投产可用”为准）

> 工作量为小团队粗估（含测试），仅供排期参考。

### P0：让已宣称的能力真正可用（1~3 个月）
1. **供应链闭环**（3~6 周）：采购/销售订单创建-审核-下达-收发货-库存联动-执行量回写；价格/配额/变更历史接线；发票→应收应付挂账与凭证。
2. **生产闭环**（4~8 周）：BOM/工艺维护入口 → 生产订单创建/下达 → 领退料/报工/完工入库 → 成本归集与凭证；MRP 生成建议单据。
3. **Web 与桌面能力对齐**（3~5 周）：辅助核算/数量/外币录入、附件上传、期末结账与结转、固定资产、银行对账、自定义报表入口——否则多租户 Web 只能算“查询+录凭证”端。
4. **审批驱动单据**（1~2 周）：审批结果回写业务状态并在保存处校验；支持会签/条件。
5. **部门数据范围生效 + 供应链操作审计**（1~2 周）。

### P1：补齐竞争门槛（3~6 个月）
6. 报表合并（多账套/多法人抵消）与多组织基础模型。
7. 预算控制前置（保存/审批时校验）。
8. 电子档案自动归档 + 哈希链 + 只读保护；审计日志防篡改。
9. OpenAPI（API Key/OAuth + OpenAPI 文档）与 Webhook。
10. 资金联动：票据/融资生成凭证、利息计提、到期日历。

### P2：长期差距（6 个月以上，视产品定位取舍）
11. AI 助手（记账/问数/异常预警）、移动端、BI 自助分析、打印模板设计器、
    第三方对接生态（电商/银行/税控）、国际化（多语言/多准则）。
